# Operational evaluation

Evaluator-only criteria; do not pass this oracle or intended outcomes to workers.
All local inputs/outputs remain outside plugin source and accepted earlier homes.
No schedules, deletion, external posts, product changes or canonical JSON edits
are authorized by these criteria. The evaluator installs the candidate package
and runs actual models in both hosts. Static checks and written runbooks do not
prove scheduler or native cleanup execution. Live tests require their own scope
and authorization.

## Retro from actual earlier outcomes

Prepare one explicit input manifest per host containing scoped paths/copies and
hashes from an actual successful role invocation and an actual failed invocation.
For example, use fresh offline [PR follow-up evaluations](follow-pr-evaluation.md).
Retain original prompts, commands, results, events, saved reports and permission
diagnostics. If no failure has occurred, report that coverage as untested; do not
invent one. Preserve original bytes outside the repository and exclude later
audits or expected conclusions from worker input. State exactly what succeeded:
a successful invocation ending at authorization wait is not a completed
engineering item. Never fabricate upstream reports or repair original failed
records merely to make the retrospective easier.

Prompt only the real task: use factory-retro on this manifest, read the supplied
original outcomes/evidence, explain what helped or failed, and propose one small
improvement plus a concrete verification plan. Own output artifacts are permitted;
no source/config/canonical/resource changes, external actions or nested models.
Use available native reads and the prescribed frozen cached helper only if needed;
no target/global dependency installations. Skip unrelated personal-context refresh
and other repositories in this isolated evaluation. Do not suggest the failure cause or
proposed remedy in worker context.

Require input-derived conclusions, exact evidence attribution and meaningful
verification. An authorization wait must not become a shipped fix. Assess a
failed run's claimed cause against actual commands and permission diagnostics rather than
repeating its summary as verified fact. Either a new supported improvement or verification of existing corrected guidance is valid.
Distinguish observed wall time, invocation lifetime and explicit human-wait
intervals; unavailable compute/token/cost remains unavailable. Compare both hosts'
actual output/evidence, not matching prose. Preserve old failures alongside retries.

## Maintenance preview and repeat

Use fixtures/operations/maintenance.json as raw declared inventory. Prepare a
manifest with raw bytes/hashes and explicit mapping of placeholders to disposable
local resources/recorded allocation inputs. Preserve scenario provenance: its
ownership/current-state/native-lifecycle fields are declarations, not real probes.
For stronger local verification, the evaluator may supply actual isolated Git
status/worktree inventory/ancestry and process observations with exact commands,
outputs and limits. A standalone synthetic checkout is not magically a native
managed worktree; absent native ownership/capability remains a limit.

Give the role only that manifest and request factory-maintain preview, own output
artifacts allowed. No begin/save/finish mutation, cleanup, process termination,
archive, config edits or external calls. Classify current evidence and retain
unknowns. Expected distinctions: declared completed+clean+merged+stopped ownership
can be an archive-copy/potential native-cleanup candidate under the stated limits;
dirty/staged/untracked, active, blocked, human-wait, unmerged, unrelated and unknown-
owner resources are retained. Name-based ownership never suffices. Protected
source/decision/review/final/raw audit evidence survives every case. A merged PR
alone does not establish completion or branch ancestry. Do not force eligible
native deletion when actual resource/lifecycle evidence is absent.

Snapshot input/canonical/resource bytes before and after. Repeat unchanged in a
fresh session and the other host: same eligibility/reasons and same preview reuse,
no generated duplicate lists/actions or resource/canonical changes. A changed
observation must be attributed rather than smoothed into the earlier preview.
Any read/probe denial is a precise limitation, not a fabricated current check.

## Explicit copy/restore roundtrip, optional

Only after concrete separate authorization, select one completed local fixture
record/evidence bundle and new archive/inspection destinations. Request additive
archive copy/index, then restore copy to the new inspection destination. Verify
all original/archive/restored hashes, index path mappings and readable final
report. Canonical history and unresolved references stay byte-identical; no source
move, overwrite, owner reattachment or item reactivation. Repeating an interrupted
copy reconciles matching bytes/index instead of overwriting or deleting anything.
If not executed, record archive/restore instruction capability as untested rather
than claiming a roundtrip. Actual native removal remains separately deferred.

## Scheduling documentation and release evidence

Review bundled scheduling guidance against current official host documentation.
The prompt uses installed factory-run, an explicit absolute config path and a
three-step bound. No custom scheduler/account task is created. Record whether local Desktop scheduling,
first scheduled fire, pause/no-new-start and cross-host scheduled switch have
actually been exercised; manual helper ownership/resume checks are separate evidence.
Record actual CLI/plugin versions, prompts, reports, byte comparisons, limits and
all unexecuted checks in an evaluation report outside the repository after
review. Keep archive copying, resource deletion and schedule activation as distinct authorization boundaries.
