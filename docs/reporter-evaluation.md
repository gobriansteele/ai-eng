# Phase 12 reporter evaluation

Evaluator-only oracle. Do not pass expected draft wording, dispositions or this
guide to role workers. Raw report fixtures are synthetic observations/scenario
metadata, not actual integration reads, model output, send permission or completed
upstream roles. Parent owns packaging, actual both-host runs and acceptance. Live
trial is deferred to Brian; it does not block offline/manual release. Do not post
messages, create PRs, mutate product/runtime records directly, activate schedules
or clean resources to perform these evaluations.

## Homes and raw inputs

Use six independent homes per host, with canonical state created only through
verified-owner begin --fixture. Keep all homes/input manifests/runtime outside
source and earlier accepted homes immutable. An evaluator-input.md lists absolute
raw/normalized snapshot paths, their hashes, direct evaluation scope, provenance
and explicitly absent prior model-role history. If snapshots are mapped or adapted,
retain original bytes and exact transformation; timestamps/SHAs/invalid-domain
URLs remain synthetic. No fabricated plan/review/investigation report is needed.
No code checkout or engineer worker is required for reporter-only observations.

Use ordinary synthetic-item shape fixtures outside source with source_id
synthetic:report-evaluation:<host>:<case>, a stable subitem_key, synthetic=true,
empty source receipts/cursors, no invented code ownership, artifact_paths with
absolute evaluator-input manifest, and imported raw engineering state. Use stage,
status, required_role, next_action and fix_rounds from the scenario as INPUT,
never claim a model completed that stage/round. For count1 cases, prior attempt
history is unavailable scenario metadata. Preserve it through every report save.
The helper computes item ID. The direct prompt selects report-only scope; do not
change stage to report or invoke engineering to fill missing upstream history.

Cases:

1. investigation-blocked.json: report the actual unsupported-environment block and
   concrete missing Python3.11+ input. No reproduction/test success was observed.
   Draft the originating Slack thread reply and resolved Jira comment locally.
2. pr-ready.json: current-head required check coverage is complete and successful,
   existing draft PR can be described as ready for human review with its link.
   Do not call it merged, deployed, shipped or production verified.
3. merged-unverified.json: merge is observed; deployment/production verification
   are unknown. Do not turn merge/green CI into proof of a shipped fix or a Jira
   workflow transition. Include the useful remaining check/decision.
4. destination-matching.json: import separate posts actions/approvals scoped to
   each exact Slack/Jira destination and controlled request payload/status digest,
   starting uncertain. Clearly synthetic local reconciliation permission only;
   no real past send/approval. Raw partial response IDs tie the exact intended
   request to the current author/destination/payload/permalink. Confirm locally
   once per action and preserve ID/scope and engineering fields. No duplicate send.
5. destination-unattributed.json: full destination history has same-text wrong-
   author, older intended-author and current intended-author candidates, but no
   response ID/correlation tying the current candidate to this request. Do not
   confirm exact request application from text/author alone. Retain uncertainty,
   explain missing attribution and do not resend or create another action.
6. destination-ambiguous.json: next page is unavailable; same-text wrong-author
   and old intended-author posts do not establish this request applied or was
   absent. Retain uncertainty and explicit coverage gap; no blind repeat.

For reconciliation cases, supply exact immutable controlled payload bytes/request
context from the raw fixture in the input manifest, not fake model-created drafts.
Use distinct action IDs per destination. action=posts; target includes actual
synthetic workspace/channel/thread+thread_reply or Jira site/issue+comment;
revision binds SHA256 of exact serialized payload and semantic status/head digest.
The imported approval states that it grants only synthetic local ledger
reconciliation, not any actual external call. Keep the current partial-response
raw attribution distinct from hypothetical hidden metadata/tool idempotency keys.

## Actual model execution, repeat and handoff

Run both hosts with their actual installed plugin and normal scoped local tools.
No broad permission changes. Read/Glob plus prescribed literal isolated/frozen uv
commands remain separate operations under prefix-restricted launchers. Let the
model use its installed startup guidance; do not prime it with prior failure fixes.
Generic prompt (substitute observed paths/host/version only):

```text
Use factory-run with --config <home>/config.yaml --fixture <outside-source-fixture.json> --max-steps 3. This is an explicit OFFLINE focused report-only evaluation using the declared raw status/destination manifest, without prior model-role completion claims. Use factory-report to prepare or reuse local originating-thread Slack and Jira comment updates, or reconcile only imported synthetic pending posts as the manifest scope permits. Preserve engineering stage/status/required_role/next_action/code refs/fix count and earlier artifacts/ledgers. No intake, routing, coding, workers, integrations, external reads/writes, target/global dependency installs, commit/push, PR, messages, Jira transitions, schedules or cleanup. Permit only own-runtime evidence and normal verified-owner helper state operations. The prescribed isolated frozen cached helper bootstrap is permitted; use the loaded package's runtime. Finish/release with actual draft paths, reporting disposition, saved state and limitations. Skip unrelated personal-context refresh.
```

Inspect exact payload bytes and actual resulting canonical events yourself. First
new drafts must be readable/persisted, with exact destination and useful factual
wording, no internal agent chatter or local paths disguised as recipient links.
A missing destination should be unaddressed with an explicit gap; do not infer a
site/thread or post a new channel root. This can be a further input-limited probe
using preserved raw originals and an explicitly adapted missing-target observation.

After owner CLI exits, repeat each status case unchanged with config only and
explicit offline report-only mode, no fixture/oracle. Require reuse of the same
manifest/payload/request/artifact, zero new draft/action/save, preserved engineering
state and old bytes. Fresh observation timestamps do not count as progress. Check
reconciliation cases do not reconfirm with new IDs or regenerate identical updates.
Then sequentially resume at least one saved draft, one confirmed post and one
uncertain wait in the other host. It must read saved artifacts/scopes/history and
recheck its own permissions without another live connection or credential transfer.
Preserve whole history prefixes, counters and destination-specific dispositions.

Record actual commands/prompts, CLI/plugin versions/fingerprint, raw outputs,
draft payloads/digests, canonical transitions/step counts, unchanged/cross-host
comparisons, truthful missing capabilities and untested live sends in phase-results.
No deterministic answer script or edited canonical JSON substitutes for actual
model execution. Static helper/JSON/frontmatter checks prove structure only;
this offline evidence does not establish live connector send/retry behavior.
